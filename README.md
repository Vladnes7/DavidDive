## 2. Видео и фотографии

### Видео — 7 роликов, все с «Перванша»

Лежат в `video/`, общий вес **48 МБ**. Все стоят с `preload="none"` и постером,
поэтому на скорость загрузки страницы не влияют: файл тянется только тогда,
когда посетитель нажал play.

| Файл | Где | Длина |
|---|---|---|
| `wreck-hull.mp4` | карточка «Перванш» | 14 с |
| `tour-1-deck.mp4` | карточка «Перванш» | 30 с |
| `tour-3-hold.mp4` | карточка «Перванш» | 30 с |
| `tour-4-hold-outside.mp4` | карточка «Перванш» | 30 с |
| `tour-5-fish.mp4` | карточка «Перванш» | 18 с |
| `wreck-wide-1.mp4` | галерея | 20 с |
| `wreck-wide-2.mp4` | галерея | 30 с |

Ролики «Спускаемся по левому борту ниже» и «Остановка безопасности» убраны
по решению клиента.

**Как они сжаты.** Исходники — 50–60 fps, 184 МБ на девять файлов. Пережаты
с сохранением родного разрешения (720 по короткой стороне) и родной частоты
кадров, всё длиннее 30 секунд обрезано до 30:

```bash
ffmpeg -t 30 -i исходник.mp4 -vf "hqdn3d=1:1:2:2" \
       -c:v libx264 -crf 28 -preset slow -pix_fmt yuv420p \
       -c:a aac -b:a 64k -ac 1 -movflags +faststart video/имя.mp4
```

`hqdn3d` — слабый шумодав: подводная взвесь иначе съедает битрейт впустую.
`-crf` 26–30 — рычаг качество/вес. `+faststart` даёт видео начать играть
до полной загрузки.

Исключение — `tour-3-hold.mp4` (внутри трюма). Исходник 1088×1920, кадр почти
целиком состоит из взвеси в темноте. Он приведён к 720 по короткой стороне
и снят с `-crf 31 -vf "scale=720:-2,hqdn3d=3:2:4:4"`: на глаз разницы с crf 28
нет, а вес падает с 16 до 10 МБ.

**Постеры** (`img/poster-*.jpg`) — по одному кадру из каждого ролика, 720 px.
Кадр выбран так, чтобы попала подпись, вшитая в видео, и чтобы он не был
чёрным. Если меняете ролик — перевыпустите и постер:

```bash
ffmpeg -ss 4 -i video/имя.mp4 -frames:v 1 -vf "scale=-2:720" -q:v 4 img/poster-N.jpg
```

**Водяной знак.** На `wreck-wide-1` и `wreck-wide-2` в левом верхнем углу стоит
череп с подписью `@diving_david` — это метка самого Давида, всё в порядке.

### Фотографии

В галерее 18 фото и 2 видео. Все кадры разные — проверено перцептивным хешем,
дублей нет.

При пополнении галереи **проверяйте на повторы**: клиент дважды присылал одни
и те же снимки под разными именами файлов. Побайтовое сравнение не поможет,
картинки пережимаются. Рабочий способ — уменьшить до 9×8, перевести в серое
и сравнить соседние пиксели (dHash); расстояние Хэмминга ≤ 6 означает
«тот же кадр».

Размер для галереи — 1100 px по длинной стороне, JPEG качества ~70:

```bash
sips -s format jpeg -s formatOptions 70 -Z 1100 исходник.jpg --out img/gal-N.jpg
```

Сетка галереи режет всё под `aspect-ratio: 4/3` с `object-fit: cover`,
так что пропорции исходника значения не имеют.

## 3b. Логотип

Знак обведён в вектор из растрового исходника
`Hero photo и логотип/2026-09-05 18.13.13.jpg` скриптом-трассировщиком.

**Что было сломано и почему.** Первая версия искала контуры обходом по
пикселям отдельно для фигуры и для её дополнения, а заливку угадывала через
`fill-rule="evenodd"`. Одну и ту же границу при этом легко посчитать дважды,
и чётность съезжала: линзы маски оказывались залитыми вместо прозрачных,
часть штрихов бороды терялась, силуэт распадался. Агрессивное сглаживание
(двойной Чайкин, порог упрощения 2.2 px) добивало мелкие детали.
В `logo-duo.svg` от знака оставалась вообще одна маска — и именно этот файл
стоял фавиконкой.

**Как сделано сейчас.** Строятся точные границы между пикселями: для каждого
залитого пикселя берутся те его стороны, за которыми лежит фон. Такие рёбра
однозначно сцепляются в замкнутые петли — внешние по часовой стрелке, петли
отверстий против неё. Заливка `nonzero` после этого воспроизводит растр
точно, без допущений о вложенности. Упрощение — Дуглас-Пекер с порогом
1.2 px, одно лёгкое сглаживание, почти прямые звенья выводятся как `L`
вместо кубической кривой.

Итог: 45 петель (13 внешних, 32 отверстия), путь 16 КБ — против 28 КБ
у сломанной версии, то есть точнее и при этом почти вдвое легче.

Файлы:

| Файл | Что это | Заливка |
|---|---|---|
| встроенный `<symbol id="lg">` в `index.html` | шапка и подвал | `currentColor`, цвет задаёт CSS |
| `img/logo.svg` | отдельный файл для печати и партнёров | `#12284B` |
| `img/logo-duo.svg` | фавиконка и apple-touch-icon | тёмная плашка со скруглением + кремовый знак |

У фавиконки именно плашка, а не голый силуэт: на 16–32 px прозрачный знак
пропадает на тёмной вкладке. Проверено на 16, 32, 48 и 220 px.

**Важно:** `currentColor` не наследуется внутрь `<img>` — SVG там отдельный
документ. Поэтому в `logo.svg` цвет задан явно, а `currentColor` остался
только во встроенном `<symbol>`, где он и работает.

Перевыпустить знак (порог яркости, упрощение, сглаживание):

```bash
python3 trace3.py logo.png out.json 128 1.2 1
```

## 3c. Галерея: просмотр фотографий

Фотография в галерее — настоящая `<button>`, просмотр — нативный
`<dialog>`. `showModal()` сам даёт ловушку фокуса, Escape и инертный фон,
поэтому руками написаны только перелистывание и свайп.

- листание: кнопки, стрелки клавиатуры, свайп; свайп добавлен **сверх**
  кнопок, а не вместо них — WCAG 2.2 требует, чтобы у жеста был
  альтернативный способ управления одним указателем;
- на телефоне стрелки уходят в нижнюю панель, чтобы не лежать на фото;
  все цели нажатия 52 px;
- закрытие: крестик, клик мимо фотографии, Escape;
- после закрытия фокус возвращается на ту карточку, где человек остановился;
- соседние кадры подгружаются заранее, поэтому листается без паузы.

**Грабли.** Событие `close` у `<dialog>` не приходит, если `close()` вызван
из собственного обработчика клика. Поэтому уборка (разблокировка прокрутки,
возврат фокуса) вынесена в идемпотентную функцию `tidy()` и вызывается по
всем путям закрытия напрямую, а не только по событию.

Два видео в галерее намеренно **не** обёрнуты в кнопки — у них свои
элементы управления, перехватывать их лайтбоксом не нужно.

## 5. Что можно улучшить потом

- **WebP.** Сейчас все картинки — JPEG (на машине не было конвертера).
  WebP снял бы ещё 25–35 % веса. Когда появится `cwebp`:
  `cwebp -q 78 img/foo.jpg -o img/foo.webp`, затем обернуть в `<picture>`.
- **Отзывы.** Новый отзыв — копия блока `<article class="rev">` в первом
  `.marquee__row`. Второй ряд клонируется скриптом сам, руками его не трогать.
- **Цены** живут только в `index.html` — правятся руками в двух местах:
  в карточках и в списке `<select>` в форме заявки.

## 6. Дизайн-система (вторая версия)

**Палитра — ваша, один в один:**

| Токен | Hex | Где |
|---|---|---|
| `--ocean` Deep Ocean | `#12284B` | тёмные полосы, футер, текст на светлом |
| `--berry` Blueberry | `#0055A0` | главные кнопки, акценты |
| `--bird` Bluebird | `#438BC4` | обводки, свечение при наведении |
| `--sky` Clear Skies | `#8CC1E9` | текст на тёмном, полоса заявки |
| `--cloud` Clouds | `#FFF8E7` | фон страницы, светлые полосы |

`--bird` на кремовом даёт контраст 3.46:1 — для основного текста мало,
поэтому он только на обводках и декоре. Текст на кремовом — всегда `--ocean`.

**Шрифты:** Playfair Display (заголовки, есть кириллица) + Manrope (текст).

**Скругления:** 16 / 22 / 30 px и `999px` для кнопок-пилюль. Скругляются
карточки, кнопки, фотографии и поля формы. **Сами секции — нет:** полосы идут
во всю ширину экрана с прямыми стыками.

**Про React-компоненты из вашего ТЗ.** shadcn/Tailwind/TypeScript поставить
нельзя — сайт по вашему же условию собирается без сборщиков и фреймворков.
Поэтому:

- `marquee` — CSS-анимация `@keyframes marquee`, пауза по `:hover`,
  под `prefers-reduced-motion` лента превращается в обычную прокрутку;
- `liquid-glass-card` — `backdrop-filter: blur()` плюс внутренние блики
  в `box-shadow` (SVG-фильтр с `feTurbulence` из оригинала съедал бы
  производительность на мобильных ради эффекта, который почти не виден);
- `footer-section` — сетка 4 колонки на чистом CSS. Из оригинала убрано то,
  чего у Давида нет: подписка на рассылку, переключатель тёмной темы,
  Facebook / Twitter / LinkedIn.
